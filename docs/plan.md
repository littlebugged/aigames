# 项目方案

> 这份文档回答"做什么、给谁、怎么获客、怎么赚钱"，技术实现见 `tech-selection.md`。
> 文中标了「假设」的地方需要你确认，其余是建议方案。

---

## 1. 一句话

做一个纯前端小游戏站，**游戏自己开发**，先借助已有门户的流量跑出数据，再把这部分流量收回自己的站。

核心判断：**这个项目的资产是游戏，不是网站。** 网站只是陈列柜。把精力放在"做出一款有人愿意玩第二次的游戏"上，比把陈列柜做漂亮重要一个数量级。

---

## 2. 明确不做什么

边界比目标更能决定项目成败。以下几条是刻意排除的：

| 不做 | 原因 |
|---|---|
| 游戏聚合站（收录别人的游戏） | 撞 Google 的 scaled content abuse 政策，2026 年 3 月核心更新中招站点掉 50–80% 流量。且内容零差异化 |
| 把页面广告当主收入 | 游戏类 RPM 全类目垫底，同流量下比游戏内广告低 5–10 倍 |
| 账号体系、好友、社交功能 | 需要后端，会吃掉做游戏的时间，且对"有人玩"这件事没有边际贡献 |
| ROM / Flash 模拟器内容 | 版权几乎都不干净，商用风险不可控 |
| 第一阶段做多语言 | 先把一款游戏在一个语言市场跑通，再谈复制 |

## 3. 市场假设「需确认」

**默认按海外市场设计**，理由：

- Cloudflare 天然服务海外（国内访问不稳且无法备案）
- CrazyGames / Poki 这类能给你流量的门户，主要面向全球英文用户
- 游戏内广告的美区 eCPM 是全球最高的一档（rewarded video 约 $15–28）

**如果实际要打国内市场**，下面四项同时要改：

| | 海外 | 国内 |
|---|---|---|
| 托管 | Cloudflare Pages | 腾讯云 EdgeOne Pages / 阿里云 ESA（需备案） |
| 变现 | H5 Games Ads / Poki / CrazyGames | 国内广告联盟（多数要资质） |
| 语言 | 英文 | 中文 |
| 获客 | 门户分发 + YouTube/TikTok | 抖音/B站/小红书 + 微信生态 |

这两条路的产品逻辑不一样，**建议只选一条先做**，不要两边并行。

## 4. 产品形态

三层结构，各自有明确职责：

| 层 | 是什么 | 职责 |
|---|---|---|
| 游戏 | 每款独立的 HTML 页面 | 唯一的资产。好玩是全部要求 |
| 站 | 首页卡片墙 + 每款游戏页 | 陈列、SEO 承接、品牌识别 |
| 门户 | CrazyGames / Poki 等 | 外部流量入口，第一阶段的主力获客 |

第一阶段站和门户的关系是：**门户负责让人玩到，站负责让人记住你是谁。**

## 5. 内容策略

### 5.1 选题标准

这是整份方案里最影响成败的部分。一款游戏立项前，先过这六条：

1. **一条规则能说清**——"跳过障碍"、"接住方块"，不需要教程
2. **3 秒内明白怎么玩**——不用读文字说明
3. **单局 60 秒以内**——碎片时间能玩完一局
4. **失败让人想再来一次**，而不是想关掉
5. **能录成 15 秒短视频**——这直接决定短视频渠道能不能用
6. **单手可玩**——手机竖屏或横屏单手操作

### 5.2 反例（明确不要做）

- 需要看教程的（策略、卡牌构筑）
- 慢热的（前 5 分钟不好玩的，在网页游戏里等于不存在）
- 重叙事的（网页游戏用户不会读文本）
- 依赖大量美术素材的（你的瓶颈是时间，不是预算）

### 5.3 冷启动的内容填充「可选」

如果担心站太空，可以用 GameMonetize / Poki 的官方 embed 塞一批游戏让站看起来有内容。**合法，但零护城河**——换个人一天能复制一份。只建议作为视觉填充，不能作为核心内容。

## 6. 获客策略

按投入产出比排序，分三个阶段推进，不要一上来就全做。

### 阶段一：门户分发（主力）

把游戏上架到 CrazyGames、Poki、GameDistribution、Playgama 这类平台。**它们负责拉流量，你拿分成。**

- 这是 2026 年网页游戏最省力的流量来源，没有第二个选项能比。
- 代价：要接它们的 SDK、要过审核、内容有规范限制（比如不能有外链）。
- 好处：即使你自己的站一个访客都没有，游戏照样有人玩。

### 阶段二：短视频（放大器）

录屏 + 大字幕，发抖音 / B站 / 小红书（国内）或 YouTube Shorts / TikTok（海外）。

- 前提是选题时就满足"能录成 15 秒短视频"这条标准。
- 小游戏天生适合"魔性 / 解压"类内容，这是唯一低成本的内容杠杆。
- 一个视频爆了，可以直接给游戏带去一波集中流量。

### 阶段三：自有站 SEO（长期）

每款游戏一个独立页面，配游戏介绍、玩法说明、技巧、相似游戏推荐。

- 单页应用做不到这件事（所有游戏共用一个 URL），这是选多页架构的根本原因。
- 页面上要放实质性内容，否则就是 thin content，同样会被 scaled content abuse 打到。
- 见效慢，但是唯一能积累下来的渠道。

## 7. 变现路径

按"什么时候能拿到钱"排序：

| 优先级 | 方式 | 时机 | 量级参考 |
|---|---|---|---|
| 1 | 门户广告分成 | 上架后即有，被动 | 取决于游玩量，rewarded eCPM 美区 $15–28 / EU $8–15 / Tier-3 $1–3 |
| 2 | 游戏授权 | 游戏做完就能谈 | 非独家 $300–800 / 平台，一款可卖多个平台；独家 $5,000 起 |
| 3 | 自有站游戏内广告 | 站有流量之后 | 接入 H5 Games Ads 或门户 SDK |
| 4 | ~~页面 AdSense~~ | — | 不作为主收入，最多当零头 |

**关键认知**：门户分成和授权这两条，都**不依赖你自己的站有流量**。所以"先把游戏做出来"的回报路径比"先把站做出来"短得多。

## 8. 里程碑与判断标准

### M0 项目骨架 —— 已完成

- Vite + TS + Phaser 4 构建链路跑通
- 首页 + 一款验证用游戏
- Cloudflare Pages 部署配置就位

产出是"能跑"，不是"能上线"。

### M1 第一款达到上架标准的游戏

- 满足第 5.1 节全部六条选题标准
- 接入至少一个门户的 SDK（CrazyGames 或 Poki）
- 移动端真机试玩通过

**判断标准**：把它发给 10 个不认识的人，不需要任何解释，其中 7 个人知道怎么玩并且玩完了一局。

### M2 上架门户，拿到真实数据

- 提交审核并通过
- 拿到真实游玩量、eCPM、平均单次游玩时长

**Go 条件**：能从这个数据里算出"一款游戏的收入天花板"。算得出来就继续，算不出来说明选品或渠道有问题，先修这个再谈第二款。

### M3 第二、三款游戏，验证管线

- 确认"从立项到上架"的周期是否可控
- 复用已经跑通的模板、部署、SDK 接入流程

**判断标准**：第二款的开发时间明显短于第一款，说明管线成型了。

### M4 自有站 + 广告

- 站有内容（每款游戏有实质页面内容）
- 接入站内广告
- 完成 SEO 基础（sitemap、结构化数据、canonical）

到这一步才开始认真做站——**不是因为它不重要，而是因为在此之前做它没有意义。**

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 中国大陆访问不稳 | 国内用户基本打不开 | 已确认走 Cloudflare，即默认放弃国内直连。真要打国内就换托管（见第 3 节） |
| 门户审核不通过 | 拿不到主力流量 | 提交前严格对照平台的 SDK 规范和内容规范；同时申请 2–3 家，不要押一家 |
| 做游戏比想象中慢 | 里程碑无限后延 | 第一款刻意做小。单局 60 秒、一条规则、无美术素材，目标周期以周计而不是以月计 |
| 游戏做出来没人玩 | 没有收入，也没有反馈 | 这正是 M2 要解决的问题——先借门户流量验证，别等自建站 |
| 每次 push 都触发构建 | 撞 500 次/月上限 | 小改动先在 `feat/*` 分支用预览环境验证，攒一批再合 main |

## 10. 需要你确认的假设

1. **目标市场**：海外优先（本文默认），还是国内？——这一条会连带改掉托管、变现、语言、渠道四项。
2. **你的时间预算**：每周能投入几小时？这决定 M1 的周期，也决定第一款游戏应该做多小。
3. **是否接受"先上架门户"**：这意味着一部分内容规范要听平台的（不能放外链、不能导流到自己的站）。
