# 架构与技术选型

## 1. 目标与取舍

| 目标 | 做法 |
| --- | --- |
| 打开即玩、全平台 | 纯前端静态站；Canvas2D 渲染，零运行时依赖；首屏 JS 约 80 KB（gzip） |
| 长期可维护 | 模拟层与渲染/界面/音频完全解耦，内容全部数据驱动 |
| 能自动验证 | 模拟层不依赖浏览器 API，Node 里可以让机器人打完整局；浏览器侧有无头 e2e |
| SEO 与分享 | 静态 HTML（含可抓取的玩法说明 / FAQ / 指南 / 结构化数据），由同一份数据生成 |
| 低端设备也流畅 | 预渲染精灵 + 对象池 + 空间哈希；自适应画质 |

**为什么不用游戏引擎 / 框架**：玩法是"大量实体 + 克制的特效"，Canvas2D 足够；自研的引擎与渲染部分约 4k 行，换来的是首包小、没有引擎升级包袱、模拟层可以脱离浏览器测试。UI 用原生 DOM + 一个不到 100 行的 `h()` 构建函数，没有引入 UI 框架。

## 2. 分层

```
data ──► game (模拟) ──events──► render / audio / hud
              ▲                          │
            input ◄──── app (主循环、状态机、存档) ◄── ui (DOM 界面)
```

- **`src/data`**：内容定义与平衡参数（`tuning.ts`）。新增内容先在 `ids.ts` 登记，TypeScript 会提示所有需要补齐的地方。
- **`src/game`**：`World` 是唯一的权威状态，`update(dt, input)` 推进一步；阶段有 `play | levelup | won | lost`。`Director` 负责刷怪节奏，`bosses.ts` 是三个 Boss 的多阶段脚本，`offers.ts` 生成升级三选一并处理进化，`progress.ts` 负责存档、结算、成就、机库购买（纯函数，可单测）。
- **事件而非回调**：模拟层通过 `world.sink = (e: GameEvent) => …` 向外发出事件（击杀、受击、拾取、Boss 阶段…）。渲染器用它生成粒子/震屏，音频用它发声，HUD 用它弹提示——模拟层完全不知道它们存在。
- **确定性**：所有随机来自带种子的 `RNG`；相同种子 + 相同输入得到完全相同的结果（有测试守护）。这让平衡模拟和 bug 复现都变得可靠。
- **`src/render`**：只读 `World` 并绘制。精灵（敌人、子弹、灯、宝石、飞船、Boss）启动时预渲染到离屏画布；泛光带阈值：主画布降采样到 1/2、1/4，在 1/4 分辨率上做阈值（两次自乘 ≈ c⁴），再降到 1/8，两层用 `screen` 混合叠回。绘制顺序保证玩家永远在所有特效之上，并垫一层暗色衬底，保证再乱也能一眼找到自己。
- **`src/app`**：主循环（固定上限的子步长，低帧率时分多步模拟以保持游戏速度）、状态机（菜单 → 出击 → 战斗 → 结算）、存档读写、PWA、自适应画质。键盘事件在捕获阶段先交给覆盖层（设置/暂停/升级/结算），被消费的按键不会再触发战斗输入。
- **`src/ui`**：每个屏幕实现 `{ el, refresh(), onKey? }`，不持有全局状态，通过 `UiCtx` 访问存档与操作入口。
- **吸附/追踪不要用"朝目标加速 + 限速"**：切向速度不会被消掉，会在 `v²/a` 的半径上形成稳定轨道（旧版经验石在 ~230px 外绕着飞机转，几十颗收不走，手机摇杆一直在动时最明显）。现在是"速度转向"——目标速度 = 朝玩家的速度（随吸附时间加速）+ 玩家自己的速度，几十毫秒内切向分量被拉直，且与帧率无关（`tests/pickups.test.ts` 在 30/60/120 fps 下守护）。

## 3. 渲染与性能

关键经验（都有实测数据，见 `node scripts/e2e.mjs perf`）：

- **`imageSmoothingQuality` 不要设成 `'high'`**。在 GPU 加速的画布上它会触发逐帧 mipmap / 双三次采样，泛光的三次降采样会因此慢 6～10 倍（同一局面 10 fps → 60 fps）。对 2:1 降采样来说，双线性本身就是正确的盒式滤波。
- 画质分三档（`high / medium / low`），区别在：像素预算上限（3.4 / 2.1 / 1.2 MP）、DPR 上限、泛光开关、粒子密度与上限、星云。"自动"从 `high`（触屏设备从 `medium`）起步，帧间隔 EMA 持续超过 22 ms 就降一档，且只降不升，避免来回抖动。
- 暂停、升级选择时给渲染器传 `animDt = 0`，粒子与镜头定格，画面不"漂"。
- 实测（Apple Silicon，Metal，约 320 个敌人同屏）：high / medium / low 在 DPR 1 与 DPR 2 下均稳定 60 fps；纯软件光栅化下 low 档 60 fps。

### 美术方向：哑光硬表面（v1.4）

起因是玩家反馈"发光的美术有点廉价"。根因不是某一处颜色，而是整套做法：霓虹线框（`shadowBlur` 烘出来的发光描边）+ 半透明填充 + 到处叠加的加色光晕 + 对整张画面无阈值的泛光——人潮里糊成一团粉雾，所有东西都像同一种"发光塑料"。v1.4 把它整体换成**哑光硬表面**。改美术时请遵守下面这些规则：

1. **机体是不透明实心的**，外沿一圈深墨描边（`INK`：先用 2 倍线宽描一遍再填充，只留外半圈）；精灵里不再用 `shadowBlur` 烘焙发光。
2. **明暗靠渐变 + 楔形面 + 轮廓光**：各面按 `light` 方向（默认 −0.7 rad）受光；颜色由 HSL 推导（`tonesOf`：高光 / 中间 / 阴影 / 深影，阴影往蓝偏 ≤10°，黄绿色相额外提亮，避免阴影发泥）。**不要用 RGB 往海军蓝混色**（得到的是橄榄色泥巴）。
3. **自发光只在灯位**：`lamp()` 是一粒小而实的灯（深色底座 + 径向渐变灯体 + 半径约 2.2 倍的极小加色光晕），不是整块发光。
4. **脚下有接触阴影**（`bank.shadow`，所有敌人的阴影先批量画完再画机体；半径 < 9 的小怪跳过，省一半张数；`low` 画质关闭）。
5. **子弹与碎片是实心的**：敌方子弹是带墨描边的圆珠（`bead`），碎片是 `source-over` 的实心三角；加色混合（`lighter`）只留给火花 / 爆炸 / 光束，而且收窄。
6. **泛光有阈值**：`bloomPass` 先降到 1/4 分辨率，再自乘两次（≈ c⁴：高光 0.9→0.66，中间调 0.5→0.06），所以只有弹芯聚成一团、爆炸、光束、大面积的亮才会晕开。阈值放在 1/4 而不是 1/2 分辨率，纯软件光栅化下省下约一半泛光耗时；代价是单颗小子弹不再有晕，符合"克制"。
7. **背景暗而安静**：点阵 + 十字标记取代整张网格线；星区调色盘整体压暗、降饱和；Boss 暗角是暗红、呼吸幅度小。
8. **Boss 预警是"危险区"画法**：淡底色 + 缓慢流动的斜纹警示带（`hatch`，整组平行四边形一次 `fill`）+ 利落边线，中线先虚后实，临出手（进度 > 78%）整块快闪；不用加色光。
9. **DOM 界面是同一套语言**：不再有任何彩色外发光（`box-shadow` / `text-shadow` / `drop-shadow`），按钮、卡片、图标底板改成"顶部高光边 + 深色投影 + 细描边"，图标底板是石墨色渐变块而不是径向光斑；标题是金属渐变（`.logo-en .l1`）；站点图标与分享图也是同样的风格（`scripts/gen-assets.mjs`：图标直接用游戏里的真实精灵合成）。

代码结构：

- `src/render/matte.ts` 是着色工具包——`hull`（描边 + 渐变底 + 楔形面 + 轮廓光）、`plate`（嵌入 / 凸起的斜面板）、`groove`（刻线）、`rivet`、`lamp`、`roundRect`、`tonesOf`。敌人（`creatures.ts`）、飞船（`shipart.ts`）、Boss（`bossart.ts`）都用它组合出来，新增造型时先在这里找零件；多部件造型共用的小工具在 `parts.ts`（见下面 v1.5）。
- 精灵以 2.5 倍分辨率预渲染（`SpriteBank(2.5)` / `BossArt(2.5)`），因为不再有外发光，边距从 +16 缩到约 +8；`Creature.faces` 为真的造型朝运动方向转身（带平滑，不会一帧翻过去），其余缓慢自转；受击闪白是**纯白剪影**（不是加亮）。
- **改美术后必须跑 `node scripts/e2e.mjs art`**：它把全部精灵放大 3.4 倍摆在几张图上（敌人 / 飞船 / 拾取物 / 武器部件 / Boss，每个下面还有 1× 原尺寸对照），写到 `.e2e/art-*.png`。美术问题（轮廓糊、阴影发泥、造型像别的东西）在 1× 的游戏画面里很难发现，在图鉴里一眼就能看到。
- 其余调试手段见 `docs/OPERATIONS.md`：`play --tele 1` 摆 Boss 预警、`--touch 1` 按手机方式开、`perf --eval` 做渲染耗时的 A/B。

### 美术方向 v1.5：轮廓优先 + 拼装式造型

起因是玩家反馈"看不出形状来，只有三角形、圆形、正方形，有点敷衍"。v1.4 解决的是"质感"，但每个敌人仍然是**一个多边形 + 几条刻线**——换了材质，轮廓还是那几种几何体，人潮里分不出谁是谁。v1.5 的原则是 **先有轮廓，再谈质感**：把敌人 / 飞船 / Boss 从"一个形状"改成"一堆部件拼成的生物或机器"，遮住颜色只看剪影也能认出是谁。

规则（改美术时请遵守）：

1. **轮廓优先**：先问"把它涂成纯黑，还能认出是什么吗？"。每种敌人有一个一句话能说清的形象——无人机 = 黄蜂（锯齿翅 + 分节腹部 + 毒刺 + 颚），蜂群体 = 六足螨，重装巨兽 = 甲虫（钳 + 侧刺），炮手 = 带炮管的炮塔虫，裂变体 = 三叶结合体，冲锋者 = 长矛头 + 弯角，自爆怪 = 12 根尖刺的水雷，护盾者 = 八角核心 + 弧形盾，幽灵 = 破布斗篷，碎片 = 五棱晶簇。
2. **主色在躯干，附肢更亮**：背景是深色，轮廓可读性取决于**亮度对比**而不是色相。躯干用敌人的主色，翅 / 腿 / 角用 `bone()`（同色相的浅色），钳 / 炮管 / 盾用 `metal()`（冷灰）。附肢比躯干**暗**会直接"消失"在背景里（做过，教训）。
3. **每个部件自己上渐变**（`cx / cy` 取部件包围盒），不要整只生物共用一个渐变，否则后排部件会全黑；**左右镜像的部件用 `flip` + 镜像的 `light`**，两侧才受光一致（堡垒号上下两个货舱曾经一亮一暗）。
4. **美术半径 ≈ 判定半径的 1.15～1.5 倍**（`Creature.scale`），`reach` 决定画布边距。判定半径不变——这是视觉改动，不是平衡改动；代价是附肢会伸出判定圈之外，属于有意为之。
5. **全部预渲染**（`SpriteBank`，2.5 倍超采样）：多出来的部件只增加启动时的一次绘制，运行时仍然是一次 `drawImage`。受击闪白是对成品做 `source-atop` 盖白。实测 GPU（Metal，DPR 2，320 敌）60 fps 不变；纯软件光栅化 DPR 1 比 v1.4 略快（≈ 38–41 vs 35–36 fps）。
6. **精英怪按判定半径放大精灵**（`e.r / def.radius`），看到的大小和吃到的伤害一致。

代码结构：

- `src/render/parts.ts`：多部件造型的共用工具——`solid`（一个带描边的实心部件）、`poly / blob / mirror / flipY / bounds`（点集处理）、`socket`（带灯的眼窝 / 镜头）、`limb / line`（肢节）、`bone / metal / dark`（三种常用色调）。
- `src/render/creatures.ts`：10 种敌人，导出 `CREATURES: Record<EnemyShape, Creature>`（`scale / reach / faces / paint`）。`EnemyShape` 是生物名（`wasp / mite / beetle / spitter / twin / ram / mine / aegis / wraith / crystal`），不再是几何体名。
- `src/render/shipart.ts`：4 艘飞船，导出 `SHIP_ART`（`reach / engines / paint`）；`engines` 同时决定尾焰喷口的位置。
- `src/render/bossart.ts`：监察者 = 机械眼（光圈叶片 + 六条钳臂），分形核心 = 十二瓣晶体星 + 轨道碎晶，虚空之喉 = 双排獠牙 + 弯角的旋涡。
- UI 与静态页：机库 / 结算里的飞船是 `shipPortrait()`（局内同一套部件画一张机头朝上、带尾焰的立绘）；玩法指南里的图鉴图片是 `node scripts/gen-sprites.mjs` 从真实精灵导出的 WebP（`public/img/sprites/`，已提交；`tests/assets.test.ts` 守护文件齐全）。**新增敌人 / 飞船 / Boss 或改了它们的美术后，要重跑这个脚本。**
- 宝石按档位用四种切工（碎晶 / 祖母绿 / 明亮式 / 晶簇），不只是颜色和大小不同。
- 验证：`node scripts/e2e.mjs art` 现在还会输出 `art-bosses-assembled.png`（用游戏里同一套绘制函数拼出的三个 Boss 整机）；`node scripts/e2e.mjs zoo` 把全部敌人以真实游戏的朝向和比例摆成一排，`--dpr 2 --clip x,y,w,h` 看细节；新造型先在 `zoo` 里过一遍，再进游戏里看人潮中的辨识度。

### 美术方向 v1.6：拾取物与武器小件也先有轮廓

v1.5 只重做了"活物"（敌人 / 飞船 / Boss），场上最常出现的另一批东西还是旧写法：拾取物是"一个彩色圆 / 八边形 + 里面一道白线图标"（回血和磁铁甚至是同一个圆），环绕刃是菱形、飞轮是四尖星、僚机是三角箭头、地雷是一个转动的菱形。v1.6 对它们用同一条原则：**把它涂成纯黑，还能认出是什么吗？**

| 对象 | 造型 | 辨识线索 |
| --- | --- | --- |
| 修复包 | 圆角十字医疗箱 + 白色十字嵌板 + 四颗铆钉 | 唯一的十字轮廓 |
| 磁力核心 | U 形马蹄磁铁，银白磁极，两极之间两道磁力线 | 唯一有"开口"的轮廓 |
| 脉冲炸弹 | 钢色圆炸弹 + 彩色腰带 + 金属帽 + 绳引信 + 火花 | 圆 + 引信的剪影 |
| 补给箱 | 弧顶木箱 + 金色包边 + 带钥匙孔的锁；场上另有一道光柱 | 方箱 + 弧盖 |
| 晶核箱 | 底座上的紫晶 + 两颗碎晶（高光是斜亮斑，**不能画成十字星**，会被当成回血） | 尖顶的晶体 |
| 环绕刃 | 弯月镰刀：护手 + 刀柄 + 两个斜面（凸脊一侧暗、刃口一侧亮）+ 一道棱 | 弯钩的剪影；进化后是金色 |
| 回旋飞轮 | 八枚朝转向弯钩的锯齿 + 金属环 + 中心孔 | 钩状锯齿 |
| 僚机 | 后掠翼微型战机：机头炮管、座舱、尾喷口、翼尖灯 | 带翼的十字剪影 |
| 磁暴地雷 | 六根尖刺的圆盘 + 中心信号灯；布设中半透明且略小 | 带刺的圆 |
| 脉冲弹 | 尖头金属弹丸 + 白热弹芯 + 身后一线曳光（进化后的等离子弹是旋涡状能量球） | 有头有尾的弹体 |

代码结构与约定：

- `src/render/props.ts` 只负责"画"（`paintHeal / paintMagnet / paintBomb / paintChest / paintCache / paintBlade / paintChakram / paintDrone / paintMine / paintBolt / paintPlasma`，都接受 `(ctx, 基准半径, 颜色)`，原点在精灵中心）；尺寸、光晕、缓存、`SpriteBank` 的取用方式仍在 `sprites.ts`。想改某个造型，只动 `props.ts` 的对应函数。
- 拾取物的 ID 与识别色在 `src/data/ids.ts`（`PICKUP_IDS`）与 `src/data/pickups.ts`（`PICKUP_COLOR`）——渲染器和玩法指南页共用同一份；`PickupKind` 是 `PickupId` 的别名。
- `cut()`（刻面宝石着色）从 `sprites.ts` 搬到了 `parts.ts`，宝石和晶核箱共用。
- **判定半径一律不变**：这是视觉改动。僚机、地雷画得比原来大一圈，是美术半径变大，不是判定变大。
- 性能：全部预渲染。脉冲弹由"两条线 + 一团光"换成"一张精灵"，每发多一次 `rotate + drawImage`；以"6 把武器全部进化"为场景做过 A/B（`perf --eval`，软件光栅化 DPR 1），和 v1.5 都在 34–35 fps，没有差别。
- 玩法指南新增「拾取物」一节（`scripts/gen-pages.ts`，图来自 `gen-sprites.mjs` 导出的 `pickup-*.webp`——**不带光晕的版本**，`SpriteBank.pickupBare()`）；`tests/assets.test.ts` 检查每种拾取物都有识别色、中英文名称和立绘。
- 验证：`node scripts/e2e.mjs art --scale 8 --only pickups,weapons` 只排这两组；再加 `--items blade,mine` 只放大指定条目（`--sheeth` 调整画布高度）。局内看实物用 `play --gear orbit,chakram,drone,mine --glv 6 [--evo 1] --dpr 3 --clip x,y,w,h`（开局直接发武器）和 `play --pickups 1`（清场后把五种拾取物摆成一排并暂停）。

### 美术方向 v1.7：光束与弹幕也先有结构

v1.6 之后，场上还剩两类东西是旧写法：**光束类武器**（棱镜激光 / 磁轨炮 / 电弧链 / 冲击波）全是"一条渐变光带 + 一圈辉光"，边缘是糊的、一粗就是一片白，四把武器看上去是同一种东西；**敌人和 Boss 的子弹**全是同一颗带描边的实心球，炮手的黄球、监察者的粉球、分形核心的绿球只有颜色不同——躲弹幕靠的是颜色而不是形状。v1.7 用同一条原则处理：**先有结构，再谈光**。

光束类（运行时每帧画，长度 / 粗细都在变，没法预渲染；全部在 `lighter` 混合下画，除了墨色的边没有任何 `shadowBlur`）：

| 对象 | 结构 | 辨识线索 |
| --- | --- | --- |
| 棱镜激光（`laser`） | 硬边管体 + 两条边轨 + 内层亮带 + 白芯；沿光束向外流动的能量包；管体外各有一条偏色 ±48° 的色散细线；枪口是一枚棱镜 | 有色散、有流动的"管子"；进化后的奶油色会被拉回金色（`tone()`），不再是一根白柱 |
| 磁轨炮（`rail`） | 极细的白芯 + 绕着它反向旋转的双螺旋尾流；出膛时一圈冲击弧 + 四角星芒，随寿命收缩 | 细芯 + 螺旋 |
| 磁轨灼痕（`scar`，进化后留在原地） | 一道每帧重新抖动的裂缝 + 乱跳的火星 | 还在烧的裂缝 |
| 电弧链（`paintBolt`） | 同一条抖动路径叠三层（宽光 / 主线 / 白芯——旧版三层各抖各的，白线总是错位）+ 分叉的小枝 + 每个落点的星爆 | 分叉的闪电 + 节点星爆 |
| 冲击波（`paintRing`） | 有厚度的波前（外缘亮、向内渐隐）+ 分段旋转的装甲环 + 向内的速度线；**敌方的环外缘长一圈朝外的尖齿**、饱和度更高 | 友方光滑 / 敌方带齿 |
| Boss 射线（`boss`） | 红 / 绿的警戒管体 + 沿光束流动的斜纹危险条 + 白芯 | 带斜纹的就是"别站进去" |
| 爆炸（`drawBlasts`） | 原来的闪光芯 + 冲击环之外，加十道长短不一的星芒，随寿命外扩淡出 | 有"炸开"的剪影 |

敌方子弹（预渲染精灵，朝 +x，原点 = 判定圆心，画布 `EBULLET_BOX` 40×26，按 `b.r / 6` 缩放，不透明 + 墨色描边）：

| 谁发射 | `kind` | 造型 |
| --- | --- | --- |
| 炮手 | `glob` | 酸液团：水滴形头部 + 拖尾 + 一滴分离的小液滴 |
| 监察者 | `lens` | 瞳孔弹：虹膜渐变 + 深色瞳孔 + 高光；是圆的，不随弹道旋转 |
| 监察者 / 分形核心 | `needle` | 飞镖：三角箭头 + 金属杆 + 后掠尾翼（场上最快的子弹） |
| 分形核心 | `shard` | 晶刺：六点刻面晶体 |
| 虚空之喉 | `fang` | 獠牙：弯曲的牙，根部圆钝、尖端象牙白 |
| —（后备） | `orb` | 通用实心弹珠；游戏里已没有人发射，保留作为新增弹种时的后备造型 |

约定：

- **敌方弹一律是带墨色描边的不透明体（危险），玩家弹丸是加色的光（友好）**——这条分界线不要打破，否则弹幕里分不清哪些是自己的。
- `src/data/ids.ts` 登记 `EBULLET_KINDS / EBulletKind`、`BEAM_STYLES / BeamStyle`、`HAZARD_IDS`。`EnemyBullet.kind`、`Beam.style` 是**纯外观字段**，不参与判定：子弹的判定半径 `b.r`、光束的判定宽度 `width / 2` 都没变。发射方在 `spawnEnemyBullet(..., { kind })` / `addBeam().style = …` 里指定。
- `src/render/bullets.ts` 只负责"画"五种子弹（`EBULLET_PAINT`）；缓存与取用在 `SpriteBank.ebullet(kind, color)`；`ebulletHi(kind, color, ss)` 只给导出指南小图用。新增弹种：在 `EBULLET_KINDS` 加一项 → 在 `bullets.ts` 写画法 → 发射处传 `kind` → `HAZARD_IDS` / `HAZARD_COLOR` / i18n（`hazard.*`）/ 指南文案补一行 → 重跑 `node scripts/gen-sprites.mjs`。`tests/hazards.test.ts`（每种造型有画法、画得干净、不超出精灵画布、Boss / 炮手确实在用）和 `tests/assets.test.ts`（立绘齐全）会拦住漏掉的大部分步骤。
- `src/render/beams.ts` 画光束 / 电弧 / 冲击环（`paintBeam / paintBolt / paintRing`），`Renderer.paint` 把它们暴露给导出脚本，`renderer.ts` 的 `drawBeams / drawBolts / drawRings` 只负责算出强度、宽度再调用。
- 敌方子弹直接写屏幕矩阵（`setTransform`，和绘制敌人同一个办法），不用 `save / translate / rotate / scale / restore`——弹幕战里一屏上百颗，这一项省下的比造型本身多出来的还多。
- 玩法指南新增「弹幕与危险」一节（五种子弹 + Boss 射线 + 冲击环；图来自 `gen-sprites.mjs`，子弹用 8× 超采样单独再画一份，射线 / 冲击环直接调 `renderer.paint` 画到透明画布上）。
- 性能：最坏情况的合成场景（7 条常驻光束 + 3 个冲击环 + 3 条长电弧 + 220 颗敌方子弹，软件光栅化 DPR 1，`perf --eval`）渲染 ≈ 22 ms → 26 ms（34 → 30 fps），逐类测：子弹 ≈ +0.5 ms / 220 颗，光束 ≈ +0.2 ms / 条；真实对局里同屏光束不超过三五条。GPU（Metal，DPR 2）同一场景两个版本都是 60 fps，JS 录制时间 0.5 → 0.6–0.7 ms。
- 验证：`play --lab fx --w 1280 --h 720 [--dpr 3 --clip x,y,w,h]` 摆一张"样张"（激光 / 磁轨 / 灼痕 / 电弧 / 冲击波 / 敌方环 / 全部子弹 / 敌方射线 / 三个寿命阶段的爆炸）；`play --catch beams|bolts|rings|ebullets|hbeams|hrings [--skip N]` 在真实对局里等到该效果出现再定格（`--ff` 取小一点，避开进化白闪）；`art --only bullets` 排出子弹图鉴。

### 图标系统 v1.8：物件图标 + 功能图标

v1.7 之后，局内的敌人、拾取物、武器、光束、弹幕都有了结构，唯一还停在"一笔画的描边线条"的是 **UI 图标**：HUD 槽位、升级卡、暂停构筑栏、机库、玩法指南里的 47 个小图标和局内精灵不是一个世界，缩到 20 px 的槽位里更是一团细线。v1.8 把它们分成两套语言重画，**全部仍由代码生成（`src/ui/icons.ts`，只返回 SVG 字符串，不碰 DOM，Node 里生成静态页时同样可用），没有引入任何第三方图标集**——README 里"全部程序化绘制"的承诺不变。接口没动：`weaponIcon / passiveIcon(id, cls)`（`viewBox` 32）、`uiIcon(name, cls)`（`viewBox` 24）和 `WEAPON_ICON / PASSIVE_ICON / UI_ICON` 三张表。

| | 物件图标（10 武器 + 12 被动） | 功能图标（25 个：播放 / 暂停 / 锁 / 齿轮 / 奖杯 / 骷髅……） |
| --- | --- | --- |
| 语言 | 和局内精灵同一套"哑光硬表面"：墨线描边 + 三层明暗 + 钢件与强调色分开 | 实心双色符号，不描边，几何统一（圆角、笔画粗细、留白一致），镂空用 `evenodd` |
| 颜色 | 主色 = `currentColor`（外层 CSS `color: var(--c)`，进化后的槽位是金色）；暗面 / 高光是**黑白半透明叠层**，所以任何主色自带明暗；钢件走 `STEEL` 五阶色板 | 全部跟随文字色，暗面是 `#000` 半透明叠层，不写死墨色 |
| 构图 | **一个图标一件物件**，先保证 20 px 下读得出剪影；铆钉、刻线这类细节只在 60 px+ 才露出；光源固定左上 | 单一符号，不拼贴 |
| 来源 | 武器尽量取自局内造型（环绕刃的弯刀、飞轮的锯盘、磁轨炮的钢轨与线圈）；被动画成具体的东西（磁铁、盾、放大镜、四叶草、仪表盘……） | — |

- 分层 DSL（`body / shade / light / flat / line / tube`）：`body()` 画墨线描边的实体，用的是 `paint-order: stroke`——只露出描边**外侧**的一半，所以描边不会吃掉形体；`fit(cx, cy, k, …)` 按视觉中心把一组形状缩放到画布正中，专治"画得偏 / 被裁掉"。
- 只用 `<path>` 与 `<g>`（体积小、CSS 好控、不引入滤镜）；颜色只写 `currentColor` / 十六进制；坐标保留两位小数。整套图标会被内联进每个页面，所以体积有上限（测试守）。
- **改图标的流程**：`npm run icons` 出样张（每个图标一张设计稿大图 + 四种真实使用尺寸，`--only weapons,ui` / `--ids chakram,rail` 只看一部分，`--w 760 --dpr 2` 在窄视口里看细节）；`npm run icons -- --check` 在无头浏览器里量每个图标**实际绘制出的范围**，越界（会被裁掉）报错退出，同时提示"偏小 / 偏心"。两者都直接 import 源码，不需要先 build。
- `tests/icons.test.ts` 守结构与风格：每个武器 / 被动都有图标且没有多余的；只有 `path / g`；坐标全是有限数；颜色格式合法；物件图标必须是"墨线 + 多层明暗 + 跟随主题色"、不许退回单线条；功能图标必须是实心、不描边、颜色跟随文字色；任意两个图标的图元不相同；体积上限。
- **尺寸（`main.css`）**：槽位与升级芯片的图标占 76%，升级卡 46 px（手机横排 40 px、小屏 32 px），机库 38 px，指南表格 28 px，按钮内 30 px；投影统一降到 0.45 透明度——不再靠发光撑存在感。

**顺手修掉的一个老 bug：自定义属性必须用 `style.setProperty`**。`Object.assign(el.style, { '--c': color })` 对 CSS 自定义属性是**静默无效**的（只是给 JS 对象多挂了一个普通属性），而 `dom.ts` 的 `h()` 一直是这么写的——所以所有 `style: { '--c': … }` 从来没生效过，HUD 槽位、升级卡、暂停构筑栏、机库、出击页里每件武器 / 被动的主题色全部落在 CSS 默认的青色上。现在 `h()` 统一走 `applyStyle()`：以 `--` 开头的键用 `setProperty`，其余直接赋值，`null / undefined / false` 跳过。**以后要写自定义属性，一律走 `h()` 或 `applyStyle()`，不要手写 `Object.assign(el.style, …)`**；`tests/dom.test.ts` 守 `applyStyle` 本身，e2e `flows` 再在真实浏览器里断言升级卡与 HUD 槽位的计算样式 `--c` 确实非空且各不相同。这次修复会让许多界面的颜色一下子变得丰富——是预期行为，不是回归。

### 打击感：伤害数字分档与武器进化演出

分层与前面一致：**参数与纯函数放 `src/engine/feel.ts`**（不依赖 DOM / Canvas），渲染器、音频、HUD、App 共用，并能在 Node 里直接单测；真正"画出来"的部分在 `render/floattext.ts`（飘字池）、`render/numfont.ts`（字形图集）、`renderer.ts`、`app/app.ts`。

**伤害数字 8 档**（`DMG_TIERS`）：冷灰小字 → 冰白 → 纯白（青光）→ 暖黄 → 橙 → 红 → 品红 → 金白，字号约每档 ×1.2，越狠停留越久、弹出越夸张；暴击额外上浮一档（至少落在第 2 档）。阈值（10 / 20 / 40 / 80 / 160 / 350 / 800）是按机器人整局的命中分布标定的——日常杂兵数字落在 T1–T2，T5 以上只占约 4%，所以"看到红/品红/金色就是重击"。**改了伤害数值体系之后要重新标定阈值**，否则梯度会整体偏移。

- **飘字限流是三个令牌桶**（小数字 / 中等 / 重击，高档可以借低档的额度），而不是一个总额度——否则人潮里几百个小数字会把重击的数字挤掉。`FloatTexts` 池容量固定（44），满池时由高档挤掉最低档里最老的一条，高档永远画在上层。
- **重击的环形冲击 / 震屏用单独的预算**（`fxBudget`），同一帧里几十次重击也只会出现几圈、震一下，不会糊成一片或让画面一直抖。
- **数字的质感是"压印的渐变字"，不是"糖果字"**（`NumLook` / `NUM_LOOKS`）：字面是"白热的顶部 → 本色 → 饱和的底部"的纵向渐变，外面一圈细而利落的暗描边，再贴着字形留一圈很窄的色光（v1.4 起光晕半径减半、只画一遍）；重击再加斜体与顶部高光。低档位（T0–T1）几乎是中性的灰白、没有光晕，**颜色只留给真正的重击**，所以满屏数字也不会花。早期版本用的"粗描边 + 彩虹色 + 感叹号后缀"一眼就廉价，不要改回去（暴击靠上浮一档表达，不再加"!"）。
- **字形图集**（`render/numfont.ts`）：每个"字符 × 外观"只预渲染一次到一张小画布（光晕 → 暗描边 → 渐变字面 → 顶部高光），之后画一个数字 = 每个字符一次 `drawImage`。`shadowBlur` 只在预渲染时用，运行时零开销，所以低画质也保留完整质感。预渲染分辨率 = 稳定字号 × 屏幕缩放 × 1.5，缩放变化超过 22%（窗口 / DPR 变化）才整体重建；字体（Orbitron）没加载好时不预渲染也不缓存，避免把后备字体的字形永久缓存下来；按字形自身宽度排版（Orbitron 的 1 比 0 窄，强行等宽会在 1 后面留洞）。

**武器进化演出**（选中进化卡 → 约 1.5 秒的时间轴，真实时间）：

1. **蓄力 0.36 s**：时间流速 1 → 0.45，向飞船收拢的光环与光点，镜头缓慢推近；
2. **爆发**：模拟层在选卡后 `EVOLVE_SHOCK.delay`（0.24 模拟秒）发出 `evolveBoom` 事件——整屏冲击环、白闪、镜头"砸一下"、DOM 铭牌式横幅（六边形徽章 + "武器进化" + 金属渐变进化名 + 描述 + 扫光，主题色取该武器的颜色）、音频 sting；
3. **定格 0.14 s**（流速 0.12）→ **0.95 s 渐渐恢复到 1**。时间流速同时作用于模拟步长与粒子，冲击波和火花会"慢放"。
4. **进化后常驻**：飞船周围的光环（每把进化武器一道各自颜色的弧线 + 虚线圈 + 漂浮光点）；进化武器开火时 `shot` 事件带 `evo` 标记，渲染加环与小幅震动、音频叠一层更厚的声音。

要点：

- **冲击波是真实的玩法效果，不是纯视觉**：`world.queueEvolveShock` → `updateShocks` → `fireEvolveShock`，对半径内敌人造成伤害与击退并抹掉敌方弹幕，玩家不受伤。参数在 `tuning.ts` 的 `EVOLVE_SHOCK`。因为它在模拟层里，`scripts/sim.ts` 的平衡数据已经包含它；动它的数值要重新跑 `npm run sim -- --all` 做对照。
- 演出的节拍由 App 里的 `cine`（演出导演）统一驱动：它只维护"已过去的真实秒数"，用 `evolveTimeScale()` 换算流速，再同时缩放模拟 `dt` 与渲染 `animDt`；暂停 / 升级面板时不走。
- **聚焦暗角**：App 每帧把"1 − 时间流速"传给 `renderer.setFocus()`，屏息 → 定格 → 恢复的过程里四周暗下去再亮回来，把视线收向飞船和冲击波；**全屏白闪按真实时间衰减**（`frame(w, animDt, realDt)`），否则定格期间它会被慢动作拖成一层迟迟不退的白雾，把暗角和冲击波都洗掉。
- 尊重无障碍设置：**减少闪烁**关闭白闪并减弱强光，**屏幕震动**关闭镜头震动与爆发时"砸一下"的变焦。
- `node scripts/e2e.mjs fx` 会在无头浏览器里：先摆一排静止的"字样本"（8 档 + 受伤数字，寿命很长、不上浮，不受截图时序影响，用来逐档对比质感），再把 8 档数字摆成梯度并截图；触发一次进化，断言武器确实进化、演出导演启动并进入爆发阶段、横幅出现，3.6 秒后导演结束（流速恢复）且横幅消失；逐帧截图写入 `.e2e/`。

### HUD 版面

HUD 按"区域 + 流式排布"组织，**不要再用 `position: absolute` + 魔法偏移把元素叠在一起**（早期版本在手机上有五六处互相遮挡）：

- 左上：生命条；顶部居中 `.hud-tc` 是一列——计时器、Boss 倒计时、Boss 血条，再往下是流式的 `.hud-stack`（通用横幅 / 进化铭牌 / Toast，自上而下排开，横幅与进化铭牌互斥——进化铭牌显示时通过 `:has()` 隐藏通用横幅）；右上：击杀数 + 暂停；左下 `.hud-bl` 是一列——教学提示、武器栏、装备栏（教学提示在装备栏上方，不会压住图标）；右下：冲刺键（触屏）；桌面的冲刺环在底部居中。左手模式把左下列与冲刺键镜像互换。
- 矮屏（`max-height: 700px / 540px`）收紧：限制同屏 Toast 条数、进化铭牌隐藏描述并缩小徽章。触屏上教学提示的最大宽度会给冲刺键让位（折行而不是伸过去）。
- 经验条把等级标签放进条内，不再单独占一行。
- **版面审计**：`node scripts/e2e.mjs layout` 在 7 种屏幕（手机竖/横、小屏手机竖/横、平板竖、桌面、小桌面）上分别摆出"满配"（6 武器 + 6 被动 + 教学提示 + 2 条 Toast + Boss 血条 + 通用横幅 + 进化铭牌）和"开局"（1 武器、无被动、只有教学提示）两种状态，在页面里量每个元素的包围盒，两两检查是否重叠、是否出屏。**开局状态不能省**：教学提示在装备栏更矮的时候紧贴冲刺键，满配状态下反而测不出来。新增或移动任何 HUD 元素后都要跑一遍。

## 4. 音频

`src/engine/audio.ts`：纯 WebAudio 合成，没有音频文件。

- 信号链：各声部 → `sfxBus` / `musicBus`（音乐带回声与闪避）→ `master` → 动态压缩 → 补偿增益 → 砖墙限幅 → 输出。限幅器保证再多声音叠在一起也不会削波。
- 音乐是程序化的：按星区选音阶和节奏，用强度值（敌人数量、进度）叠加声部，Boss 战切换到 Boss 编曲。
- 自动播放策略：首次用户手势才创建/唤醒 `AudioContext`；标签页隐藏时挂起。
- `audio.meter()` 只在 e2e 中使用，用于断言"有声音且不削波"。

## 5. 输入

`src/engine/input.ts` 统一键盘、触屏与手柄，输出归一化的 `{mx, my, dash}`。触屏是"浮动摇杆"（在屏幕左半边任意位置按下即成为摇杆中心），可在设置里切换左手模式；手柄既能控制战斗，也能在菜单里按方向键移动焦点。设备切换会自动更新界面提示（例如教程文案）。

## 6. 存档

`localStorage` 键 `neon-surge:v1`，JSON。读取时经过 `sanitize()`：数值钳制、未知字段丢弃、缺失字段补默认值，所以旧存档与手工编辑过的存档都不会让游戏崩溃。损坏的原始数据会先备份到 `neon-surge:v1:corrupt` 再重置。无法使用 `localStorage`（隐私模式等）时退化为内存存档。设置里支持导出 / 导入存档文本，方便换设备。

## 7. 静态页与 SEO

`scripts/gen-pages.ts` 在构建时用 `src/data` 与 i18n 词典生成：中英文首页（含可抓取的特色、操作、技巧与 FAQ）、游戏指南（武器进化对照表、数值表、Boss 打法、成就列表）、关于、隐私、404、`sitemap.xml`（含 hreflang）与 `robots.txt`。数据一改，指南页自动同步，不会出现"文档和游戏对不上"。页面带 canonical / Open Graph / Twitter Card / JSON-LD（VideoGame、FAQPage、WebSite、Article）。生成物都在 `.gitignore` 里，只提交源码。

## 8. PWA 与发布

- `sw.js` 由构建插件写入，缓存名带构建号；导航请求网络优先（推送后用户尽快拿到新版），失败回退缓存（离线可玩）；`/assets/` 缓存优先；预缓存清单只包含磁盘上真实存在的文件，并且逐个添加（一个失败不会拖垮其余）。
- 新版本接管页面时，菜单会出现"游戏已更新，刷新即可体验新版本"的提示；战斗中不打断，回到菜单后再提示。
- `version.json`（`{id, builtAt}`）用于部署探测；`public/_headers` 给带哈希的资源设置永久缓存，`sw.js`/`version.json` 禁止缓存。

## 10. 新增一把武器的清单

TypeScript 只会提醒前两项，其余靠这张表（漏了也有测试兜底：`tests/data.test.ts`、`tests/i18n.test.ts`、`tests/weapons.test.ts`）：

1. `src/data/ids.ts`：登记 id（编译器会提示 `WEAPONS` 与 `WEAPON_ICON` 缺项）。图标在 `src/ui/icons.ts` 的 `WEAPON_ICON` 里画——一件认得出来的小物件，尽量取自局内造型；画完 `npm run icons -- --ids <id>` 看样张，再 `npm run icons -- --check` 查越界（见"图标系统 v1.8"）。
2. `src/data/weapons.ts`：等级表 + 进化形态 + 搭档被动（搭档不能与已有武器重复）；升级卡片的文案由相邻两级数值自动生成，只需在 `shown` 里列出要展示的项。

5. `src/i18n/zh.ts` + `en.ts`：`weapon.<id>.name/desc/evoName/evoDesc`，以及需要改名的数值标签 `stat.<id>.<key>`。
6. 跑 `npx tsx scripts/bench-weapons.ts --only <id>` 与已有武器对照强度（同档位的人潮 DPS / Boss DPS 应处在同一量级）。
